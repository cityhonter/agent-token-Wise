# Token-Wise 配置文件

> 这是用户唯一需要编辑的文件。修改后保存即可，agent 会在会话中读取。
> 格式：YAML。注释以 `#` 开头。
> 冲突裁决：`protected_tasks` > 模块开关 > preset。
> **懒加载协议**：agent 默认只查本文件的 `preset` 与 `redlines.reminders` 两行，
> 其余字段按需读取对应小节——本文件保留即可，不必删除，不影响功能。
> 只有改过这里（非默认值）的字段，agent 才会实际读取。

```yaml
# ============================================================
# 第 1 层：三档预设（大多数用户只改这里）
# ============================================================
# conservative 保守：只做 L0（Context 优化），绝不压缩语义、不降模型、不动思考
# balanced     平衡：L0 全开 + L1 输出优化标准档 + L2 分级放行（默认）
# aggressive   激进：L1 严格档 + 允许 L2（compact/降档）——有降智风险，慎用
preset: balanced

# ============================================================
# 红线守则
# ============================================================
redlines:
  # 红线是条件策略（非绝对规则），行为级约束始终生效。
  # 此开关只控制 agent 是否"主动提醒"：
  #   true  = 到触发点主动提醒用户，并给出原因（默认）
  #   false = 静默遵守，不打扰；仅在用户明确违反红线时给一句简短提示
  # 强烈建议：红线最好由用户自己遵守（管理上下文生命周期 / 关注缓存命中 /
  #           索引按需 / 先规划后执行），效果远好于依赖 agent 提醒。
  reminders: true

# ============================================================
# 模块开关：输出纪律（L1，省输出 token）
# ============================================================
output_discipline:
  enabled: true
  # off=不启用  basic=只禁寒暄与复述  standard=+diff 优先  strict=+默认简版/禁过程叙述
  strictness: standard
  # 改代码默认输出：diff + 一行结果
  # 复杂修改（多文件/高风险/跨模块）自动升级为：diff + 影响范围 + 风险 + 测试结果
  # 用户要求解释时恢复详细输出（这是 L1 输出压缩，不是无损）
  diff_only: true
  # 默认回答详略：brief=简版（说"详细"才展开）  full=完整
  default_detail: brief

# ============================================================
# 模块开关：输入瘦身（L0，省输入 token）
# ============================================================
input_slim:
  enabled: true
  # 精确引用：auto（推荐）——用户给了精确位置直接用；
  #   没给 → agent 先做最小范围搜索；搜索范围明确不追问；范围巨大才询问用户
  # 不建议强制 true（会打断"登录有问题帮我看看"这类正常提问）
  force_precise_ref: auto
  # 索引地图：auto=宿主有原生索引优先用；没有且项目复杂（>500 文件）才建议 AI_INDEX.md
  #   require=复杂项目缺失时先生成再干活  off=不使用
  index_map: auto
  # 宽范围检索丢给 subagent：价值是"减少主上下文污染"，不保证省 token
  # （subagent 自身也消耗 token）。大范围探索时开启收益明显
  use_subagent_scan: true

# ============================================================
# 上下文卫生（Context Hygiene，核心模块）
# ============================================================
context_hygiene:
  # 上下文占比分级（替代写死的 token 阈值）：
  #   context_ratio = 当前上下文估算 / 模型 context window
  #   <30% 正常 | 30~50% 观察 | 50~70% 提醒整理 | 70~85% 强烈建议 | >85% 建议结束
  # 宿主不提供 usage 数据时，agent 按对话轮数与内容量级粗估，并标注"估算值"
  use_ratio_based: true
  # 收尾时强制产出"进度小结+待办+下一步"（隔夜/切会话时防失忆）
  overnight_summary: true

# ============================================================
# 思考控制（L2，默认不主动干预）
# ============================================================
thinking:
  # auto=按任务复杂度给档位  max=复杂任务全开  off=不干预（不主动调）
  mode: auto

# ============================================================
# 任务分诊（router = 策略层，不是模型切换执行器）
# ============================================================
router:
  enabled: true
  # agent 只做任务分类并"推荐"档位；实际切换由宿主决定。
  # 宿主不支持动态切换时，改为提示用户手动切模型。
  heavy_model: ""   # 例：opus / claude-sonnet-4-5 / gpt-5（复杂任务推荐）
  light_model: ""   # 例：haiku / gpt-4.1-mini / deepseek-chat（简单任务推荐）

# ============================================================
# 效果评估（把"我觉得省了"变成"测出来省了"）
# ============================================================
evaluation:
  enabled: true
  # 每任务记录：input/output tokens、cache hit（宿主提供则记）、retry/correction、
  # task_success → 估算成本与节省比，`/token-wise report` 输出报告
  # 宿主支持时写入 .token-wise/stats.json，可用 scripts/estimate_cost.py 离线算账
  save_stats: false

# ============================================================
# 任务豁免表（禁压名单）：命中则 L2 全禁，L1 仅限输出压缩
# ============================================================
# 为什么：这些任务的质量依赖完整推理链与细节，压缩/降档/关思考 = 必降智
protected_tasks:
  - architecture_design        # 架构设计
  - large_refactor             # 大规模重构
  - tricky_bug                 # 疑难 bug 排查（修正>=2次自动进名单）
  - teaching                   # 教学/解释给新人听
  - security_review            # 安全审查
  - payment                    # 支付逻辑
  - authentication             # 登录鉴权
  - authorization              # 权限控制
  - database_migration         # 数据库迁移
  - production_incident        # 生产环境故障
  - data_migration             # 数据迁移
  - performance_optimization   # 性能优化
  - api_contract_change        # API 契约变更
  - dependency_upgrade         # 依赖升级（可能有破坏性变更）
```
