# 分级闸门决策树

> 用途：agent 在每轮执行时，根据任务类型判定当前任务允许使用的省 token 手段级别。
> 判定顺序：先查保护名单，再查任务类型，最后落到 L 级别。

## 判定流程

```
任务开始
  │
  ├─ 命中 protected_tasks？───────────────────► 仅 L0 + L1(仅输出压缩) ──► 执行
  │
  ├─ 任务类型 = 简单机械类（写工具函数/重命名/查文档/简单配置）？
  │     ├─ preset=conservative  ──────────────► L0
  │     ├─ preset=balanced     ──────────────► L0 + L1
  │     └─ preset=aggressive   ──────────────► L0 + L1 + L2(允许 compact/降档)
  │
  ├─ 任务类型 = 常规开发（写业务代码/小功能/修已知 bug）？
  │     ├─ preset=conservative  ──────────────► L0
  │     ├─ preset=balanced     ──────────────► L0 + L1
  │     └─ preset=aggressive   ──────────────► L0 + L1（L2 需显式命令）
  │
  └─ 任务类型 = 复杂推理类（架构/重构/疑难 bug）？────► 强制 L0 + 规划模式（R4）
        且禁用：L2 全禁；L1 仅输出压缩；thinking 不许降档
```

## L 级别定义

| 级别 | 允许的手段 | 副作用 |
|---|---|---|
| L0 无损 | 删冗余、缓存友好排序（静态前置/动态后置）、精确引用、索引地图、subagent 隔离、输出格式约束 | 无，永远安全 |
| L1 轻度有损 | 输出压缩（禁寒暄/禁过程叙述/diff-only）、summary 型历史管理、/clear 建议 | 教学与解释场景信息密度下降，需豁免 |
| L2 重度有损 | /compact 全量压缩、模型降档（router）、关闭/降低思考 | 丢失推理链与细节，易前后矛盾，禁止用于受保护任务 |

## 自动进保护名单的信号

以下信号出现时，将当前任务自动加入 `protected_tasks`（当次会话内）：

1. 同一问题被修正 ≥2 次（说明失败尝试已污染上下文，此时应建议 /clear 重开，而非压缩）
2. 用户明确说"解释给我听 / 讲清楚为什么"（teaching 语义）
3. 任务涉及鉴权、支付、权限、密钥等安全敏感代码
4. 用户显式说"这个别省" / "保证质量优先"

## 路由与思考的配合

1. `router.enabled: true` 且配置了模型档位：简单任务用 `light_model`，复杂任务用 `heavy_model`。
2. 复杂任务强制 `thinking` 保持最大档位；只有 `protected_tasks` 之外且用户显式要求时才允许降档。
3. 路由误判的代价 = 复杂任务交给弱模型 → 必返工 → 总成本更高。拿不准时按"复杂"处理。
