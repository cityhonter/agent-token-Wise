# 提示词模板

> 用途：各场景可直接复用的提示词模板，附好坏示例对比。

## 1. 模式二：先规划后执行（红线 R4）

```
先只做规划，不要动手。输出：
1. 方案（含关键取舍）
2. 涉及的文件清单
3. 风险点
等我确认后再执行。
```

## 2. 确认开工（执行阶段零打断）

```
方案没问题，按这个执行。执行中遇到 A/B 分歧按方案里的决定处理，
不要中途弹框确认，结尾说明即可。
```

## 3. 长会话收尾（防隔夜失忆 + 防缓存白烧，红线 R2）

```
把当前进度总结成要点：
- 已完成
- 进行中
- 待办
- 下一步建议
第二天我会带着这份小结继续。
```

## 4. 新会话开局（带小结续接，红线 R1）

```
以下是我上次的进度小结，请基于它继续：
<粘贴小结>
```

## 5. 索引地图生成（红线 R3）

```
为当前项目生成 AI_INDEX.md：扫描目录结构，列出每个文件的导出符号
（函数/类/组件）与关键依赖，控制在 3000 token 以内。
之后我改代码，记得提醒我更新它。
```

## 6. 精确引用（输入瘦身）

❌ 差（模糊，AI 要全仓扫）：
```
改善这段代码
```
✅ 好（指向明确，省探索）：
```
在 src/auth/token.ts 的 refreshToken() 中，第 42 行起，
给 session timeout 场景加输入校验，不要用 mock。
```

## 7. 输出纪律（L1 输出压缩）

❌ 差（废话占输出 token）：
```
Certainly! I'd be happy to help you with that. Let me walk you through
the refactoring step by step...
```
✅ 好（信息密度拉满）：
```
重构完成：token 校验补了 edge case，错误处理已加，保持向后兼容。
```

## 8. 返工循环干预（模块 F）

```
这个问题我们已修正过 2 次。上下文可能被失败的尝试污染了，
建议 /clear 后按以下方式重新提问：<重新组织的精确 prompt>
```

## 9. 压缩前分级确认（L2 闸门）

```
当前上下文较大，我建议压缩历史（有损）。
该任务不属于 protected_tasks，压缩可能丢失部分中间推理细节。
确认压缩？回复"压缩"执行，或"继续"保持完整上下文。
```
