# Benchmark 任务集（12 个真实编码任务）

> 用途：A/B 对比 Token-Wise 效果。同一批任务分别用"默认 Agent / balanced / aggressive"跑，
> 输出 token reduction、cost reduction、task success rate、retry rate、quality regression。
> 规则：任务描述保持原样不要改写；控制变量（同模型、同项目基线）；每任务记录 stats 一条。

## 难度划分

| 难度 | 任务编号 | 特点 |
|---|---|---|
| 简单（S）| T01~T04 | 单文件、单函数、无跨模块依赖 |
| 中等（M）| T05~T08 | 2~5 文件、有明确依赖、需要读少量上下文 |
| 复杂（C）| T09~T12 | 跨模块、架构取舍、需要完整推理链 |

## 任务列表

### T01（S）工具函数：防抖+节流
**目标**：写一个同时支持防抖（debounce）和节流（throttle）的工具函数模块 `utils/timing.js`，导出两个函数，带 JSDoc。
**验收**：两个函数行为正确；边界（immediate 参数、取消）有处理；有单元测试 3 个用例通过。

### T02（S）数据清洗：日志去重
**目标**：`utils/dedupe.js`——对 JSON 日志数组按 `(timestamp, level, message)` 去重，保持首次出现顺序，输出清洗后数组与去重数量。
**验收**：用例通过；输入 1 万条性能可接受（<1s）。

### T03（S）组件：可复用的空状态组件
**目标**：Vue3 组件 `EmptyState.vue`——支持插槽、icon 类型、操作按钮，样式跟随设计系统变量。
**验收**：渲染正确；props/插槽类型齐全；不引入额外依赖。

### T04（S）配置读取：环境变量解析
**目标**：`config/env.js`——读取 `.env`，支持默认值、类型转换（boolean/number），输出冻结对象。
**验收**：缺失变量走默认值；类型转换正确；禁止输出密钥到日志。

### T05（M）修复已知 bug：轮询导致的内存泄漏
**目标**：现有 `DataUpdateManager`（约 300 行）的 `setInterval` 在组件卸载后未清理，修复泄漏并保持 100ms 轮询 + 防重入逻辑不变。
**验收**：`clear` 后无残留定时器；原有 API 不变；测试通过。

### T06（M）重构：把回调嵌套改成 async/await
**目标**：`services/api.js` 中三层回调嵌套重构为 async/await，错误处理语义保持不变（retry 一次 + 统一错误码）。
**验收**：行为等价（对比测试）；错误码映射不变；无死代码残留。

### T07（M）小功能：列表拖拽排序
**目标**：Vue3 实现拖拽排序列表（不用第三方库），支持跨列表移动、持久化到 localStorage。
**验收**：拖拽交互流畅；顺序正确持久化；边界（空列表/单元素）不报错。

### T08（M）性能优化：大列表虚拟滚动
**目标**：10 万行表格渲染改为虚拟滚动，固定行高，滚动时只渲染可视区。
**验收**：滚动流畅（帧率>50fps）；滚动位置保持；事件委托不失效。

### T09（C）架构设计：请求缓存层
**目标**：设计并实现 `services/cache-layer.js`——统一请求缓存（内存 + 可选 localStorage），支持 TTL、失效策略、并发去重（同一 key 并发只发一次请求）。
**验收**：并发去重正确；TTL 过期重新请求；错误请求不缓存；给出架构取舍说明（内存上限/淘汰策略）。

### T10（C）跨模块重构：状态管理迁移
**目标**：把组件内 `provide/inject + 事件总线` 的模式迁移到 Pinia（store 拆分 + 持久化），涉及约 6 个文件，保持对外行为不变。
**验收**：所有引用处行为一致；store 模块划分合理；旧事件总线无残留引用；迁移说明文档。

### T11（C）疑难 bug：偶发登录态丢失
**目标**：线上反馈"登录态偶尔丢失"，检查 `auth/token.js`（refresh 逻辑 + 多 tab 同步），找出竞态并修复。
**验收**：复现路径说明；竞态修复（多 tab 场景）；refresh 失败降级策略明确；测试覆盖。

### T12（C）API 契约变更：批量接口拆分
**目标**：`POST /api/items/batch` 拆成单条接口（服务端变更导致），客户端 `services/items.js` 及 3 处调用方全部适配，保持调用方 API 不变（内部并发聚合）。
**验收**：调用方零改动；并发批量正确聚合/降级（部分失败策略）；超时处理。

## 记录模板（每任务一条，进 stats.json）

```json
{
  "task": "T05 轮询内存泄漏",
  "config": "balanced",
  "model": "同组固定模型",
  "input_tokens": 0,
  "output_tokens": 0,
  "cache_hit_pct": 0,
  "retry_count": 0,
  "correction_count": 0,
  "task_success": true,
  "notes": ""
}
```

## 验收口径

- task_success：验收标准全部满足 = true；部分满足 = false（并在 notes 说明缺什么）。
- correction_count：同一任务用户要求修改的次数（agent 自查后提交的不算，用户指出问题才算）。
- retry_count：任务执行过程中 agent 主动重试/回滚的次数。
- 质量回归判定：与对照组对比，失败任务或验收打折任务必须记录具体差异。
